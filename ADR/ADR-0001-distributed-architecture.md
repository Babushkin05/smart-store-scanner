# ADR-0001: Distributed Architecture (Pi + Go Server + Cash Register)

**Date:** 2026-06-16
**Status:** Accepted

## Context

Smart Store Scanner — IoT-система для распознавания продуктов через камеру.
Raspberry Pi с камерой фотографирует товар → нейросеть распознаёт →
результат отправляется на сервер → кассовый клиент показывает чек, статистику
и графики.

Система состоит из трёх независимых компонентов.

## Decision

**Три компонента, взаимодействующие через HTTP REST API.**

```
┌─────────────────┐     POST /scan      ┌─────────────────┐     GET /stats     ┌─────────────────┐
│  Pi Client      │ ──────────────────→ │  Go Server      │ ←────────────────── │  Cash Register  │
│  (RPi + камера) │                     │  (состояние,    │                    │  (браузер)      │
│  tbn inference  │ ←──── JSON ──────── │   статистика)   │ ──── JSON ────────→ │  графики, чек   │
└─────────────────┘                     └─────────────────┘                    └─────────────────┘
```

### Компонент 1: Pi Client (`client/`)
- Работает на Raspberry Pi с камерой.
- Захватывает кадр, прогоняет через tbn-runtime.
- Отправляет результат на Go-сервер: `POST /scan {class_name, confidence}`.
- Показывает на локальном экране последний распознанный товар.

### Компонент 2: Go Server (`server/`)
- Принимает сканы от Pi-клиента.
- Хранит состояние текущей «корзины» в памяти (с optimistic concurrency — один
  Pi, одна касса).
- Ведёт историю чеков за день.
- REST API:
  - `POST /scan` — добавить товар в текущую корзину.
  - `GET /cart` — текущая корзина (состав + суммы).
  - `POST /checkout` — закрыть чек (сохранить в историю, сбросить корзину).
  - `GET /history` — история чеков за сегодня.
  - `GET /stats` — агрегированная статистика дня (выручка, популярные товары).

### Компонент 3: Cash Register Client (`cash-register/`)
- Отдельное веб-приложение (vanilla HTML/JS).
- Периодически опрашивает `GET /cart` и `GET /stats`.
- Показывает:
  - **Текущий чек** — таблица товаров, кол-во, цена, итог.
  - **Карточка последнего товара** — эмодзи, название, цена.
  - **Pie chart** — распределение товаров по типам (через Chart.js).
  - **История за день** — список закрытых чеков.
  - Кнопки: «Новый покупатель» (checkout), «Сброс».

## Alternatives Considered

### A) Монолит (всё на Pi)
Отвергнуто — нет разделения ответственности, нет централизованной статистики.

### B) Pi → Python/Flask Server
Отвергнуто — Go лучше подходит для concurrent HTTP, проще деплоить бинарём.

### C) WebSockets вместо polling
Избыточно для данной задачи. Polling раз в 2 секунды достаточен.

## Consequences

- **Positive:** Чёткое разделение: инференс на edge, логика на сервере,
  отображение на клиенте.
- **Positive:** Кассовый клиент можно открыть на любом устройстве в сети.
- **Positive:** Go-сервер — один бинарный файл, легко деплоить.
- **Negative:** Зависимость от сети между Pi и сервером.
- **Negative:** In-memory хранение — при перезапуске сервера данные теряются
  (приемлемо для демо).
